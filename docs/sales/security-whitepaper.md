# OpenCS 安全与数据主权说明（供客户安全团队评审）

本文描述 OpenCS 的安全架构、数据流与边界。所有描述均可在开源代码中核验，
关键控制点均有自动化测试守护（当前 472 项）。

## 1. 部署模型与数据主权

OpenCS 是**自托管**软件：全部组件运行在客户自己的服务器上，供应商无任何
数据回传通道、无远程管理通道、无遥测上报。

| 数据 | 存放位置 | 格式 |
|---|---|---|
| 联系人 / 渠道身份 / 时间线 | `OPENCS_DATA_DIR/crm.db` | SQLite |
| 节奏 / 发件箱 | `nurture.db` | SQLite |
| 审计与审批队列 | `audit.db` | SQLite |
| 评测与演进提案 | `evolution.db` | SQLite |
| 知识库索引 | `knowledge.db`（可由 Markdown 源重建） | SQLite FTS5 |
| 会话事件日志 | `sessions/`（逐帧回放依据） | JSONL |

备份 = 文件级操作（附带 `scripts/backup.sh` 做 WAL 一致性快照 + 轮转）。

### 模型调用的数据流（唯一的出境路径）

对话文本需要发送给 LLM 推理端点。客户可三选一：

| 模式 | 数据去向 | 适用 |
|---|---|---|
| DeepSeek 官方 API | DeepSeek（客户自己的 API 账号） | 性价比优先 |
| OpenAI 兼容端点 | 客户指定的任意 URL（自建代理 / 中转） | 已有网关体系 |
| 自建推理（vLLM / Ollama 等） | **不出机房** | 强合规场景 |

除模型调用外，OpenCS 不向任何外部服务发起请求
（可选的 Langfuse 观测默认关闭，开启与否由客户决定）。

## 2. 访问控制

| 暴露面 | 鉴权 | 说明 |
|---|---|---|
| `/admin/*`、控制台数据接口 | `Bearer OPENCS_ADMIN_TOKEN`，恒定时间比较 | 等同后台权限；生产必填 ≥16 字节 |
| `/channels/webchat` | 业务侧自行嵌入鉴权 + **每会话频控**（默认 20 条/分钟，超限 429） | 频控防刷模型账单 |
| `/channels/wecom/callback` | 企微 SHA1 签名 + AES-256-CBC 解密 + receiveid 校验 | 伪造回调返回 403 |
| `/health/*` | 开放 | 探针专用，不触碰业务数据 |

**生产环境 fail-fast**：`OPENCS_ENV=production` 下缺少管理凭证 / 动作令牌密钥，
或模型配置缺失导致将降级为 mock，**进程直接拒绝启动**，不静默运行。

## 3. Agent 动作管控：六档风险分级

LLM 在 OpenCS 中**不能直接执行任何不可逆动作**。所有副作用动作经工具层收口，
执行前经过 guard 链：租户隔离 → 风险分级 → 频控。

| 档 | 名称 | 默认策略 | 典型工具 |
|---|---|---|---|
| 0 | GREEN | 放行 | 查知识库、读订单 |
| 1 | YELLOW | 放行 | 加备注、写记忆 |
| 2 | ORANGE_A | 放行（频控） | 发模板消息 |
| 3 | ORANGE_B | 放行（频控 + 审计） | 节奏投递 |
| 4 | ORANGE_C | **人工确认** | 自由文本回复 |
| 5 | RED | **人工确认** | 改生命周期、标记成单 |

两条安全默认值：
- **未登记的工具落 ORANGE_C**——新增工具忘记分级时行为是「收紧」而非「放行」
- **自由文本回复默认进审批队列**——放开自动回复需要显式修改
  `OPENCS_AUTO_APPROVE_TIERS`，是可审计的运营决策

### 审批语义：批准的就是发出的

待审内容以**原文**呈现给运营。批准后由系统确定性投递该原文，
**不再经过模型**——不存在「审批通过后 AI 又改了措辞」的可能性。

## 4. 可审计性

- **持久化审计**：每个工具动作的裁决（allow / ask / deny）连同原因落库，重启不丢
- **Model-visible ⟺ logged**：任何进入模型请求的内容都可从会话日志重建
- **逐帧回放**：会话以事件帧（JSONL）持久化；重连 / 回放看到的历史与当时实时
  推送**逐帧一致**（两者共用同一纯投影函数，有测试守护）

## 5. Agent 自我演进的门禁

Agent 会基于低分对话提出改进提案，但：

- 涉及**行为准则**（技能话术、节奏策略）的提案**强制人工审批**，无配置可绕过
- 任何 `deprecate`（删除既有准则）动作强制人工审批
- 自动放行默认关闭；即使开启，也仅限最低风险维度且需置信度与评测双重达标

设计立场：让模型自主改写自己的行为红线，等于把「不做超范围承诺」交给它自己
决定是否遵守。这条门禁没有开关。

## 6. 已知边界（如实告知）

- 单进程部署；多实例水平扩展需切换队列组件（接口已预留，属路线图项）
- 服务重启后**进行中对话的模型上下文**重置（联系人 / 节奏 / 审批 / 审计不受影响）
- 企微适配器消息游标在内存中，重启后重拉一次增量（幂等，不重复触发回复）
- HTTPS 由客户侧反向代理（Nginx / Caddy / 负载均衡）终结，OpenCS 监听内网端口

## 7. 供应链

  （`scripts/setup-dsh.sh` 一键复现）；升级前有契约测试层定位 API 破坏面
